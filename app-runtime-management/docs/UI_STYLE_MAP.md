# App Runtime 应用管理 UI 约定

ARM-D-025：confirmed 游戏、游戏平台和游戏工具的默认管理归类显示为“受限娱乐”，系统应用的默认管理归类显示为“复合”；归类理由显示“系统默认分类”。家长仍可使用既有分类操作覆盖默认。疑似游戏继续显示未归类/建议，不得伪装为已生效分类。

ARM-D-018/ARM-D-020/ARM-D-022/ARM-D-024：应用管理五分类目录不新增左侧“游戏”分类。每个目录右侧依次显示“普通应用”“游戏”“系统应用”；三个组都支持展开／折叠并分别显示数量，“已处理历史”也按同样方式惰性展开。普通应用默认展开，游戏和系统应用的状态由用户控制；搜索命中时自动展开对应组，清除搜索后恢复用户选择。折叠组不创建产品行和分类按钮 DOM，避免长清单仍在后台完整渲染。confirmed `game/gameLauncher/gameUtility` 才进入游戏组，疑似游戏仍在普通应用；系统应用必须读取 Worker 返回的兼容 `catalogGroup=systemTool`，页面不得按名称、发布者或 `applicationOrigin` 猜测。技术记录继续只在系统管理中显示。

ARM-D-016：应用产品行必须并列呈现“产品类型”和“管理归类”，例如“游戏 · 复合”“游戏 · 受限娱乐”“疑似游戏 · 未归类”；不得把类型标签伪装为已生效分类。分类规则面板对类型规则显示命中依据、当前命中应用、建议/自动状态和目标孩子，启用自动规则前必须先预览。配额界面继续只显示管理分类配额，不增加游戏配额。

ARM-D-015：应用管理五分类目录不增加新入口。每个分类右侧同页分为“普通应用”和“系统应用”：普通应用默认展开，系统应用默认折叠并显示数量；搜索命中系统应用时自动展开。系统应用行沿用普通产品行的安装/使用状态、平台、机器/账户数、归类理由和分类操作。系统应用不是技术组件；技术组件仍只在系统管理“技术进程记录”中只读展示。

产品行不重复展示唯一、同名、`main` 且未拆分的运行入口。这类入口仍保留在 API 和策略映射中，但界面将其视为产品内部实现；只有多变体、异名入口、非 `main` 角色或已拆分管理时才显示变体数量与展开区。

ARM-D-014：应用管理主列表按产品显示。产品行包含安装/使用状态、平台、机器/账户数、变体数量和归类理由；展开后显示变体，只有执行“拆分管理”的变体提供独立分类。系统管理“技术进程记录”继续只读展示组件、维护入口、宿主和证据不足对象。盘点状态按来源显示完成、带警告或失败，不再用一个失败来源代表整机全部来源失败。

ARM-D-013：应用管理五目录只显示 `actionable` 产品/主应用，分类数量不包含组件、安装器、helper、候选或只有历史进程短名的记录。产品的多个可信平台实现显示为一个产品行；只有 actionable 行提供分类操作。系统管理增加“技术进程记录”页签，只读展示证据不足、候选、组件和瞬态记录的名称、平台、最近使用、时长及不可管理原因，不显示 raw runtimeIdentity、路径、SID 或凭据，也不提供分类按钮。

ARM-D-012（目录展示部分由 ARM-D-013 修正）：五导航/五目录和管理面板保持。目录范围提供主要应用、已安装未使用、使用未归类证据和全部可管理应用；组件/候选改由技术进程记录承载。运行证据不被隐藏角色豁免，安装未使用的可靠主应用可归类，友好名称回退明确提示。盘点状态显示批次/来源失败及未验证用户，不能以行数冒充整机完整；不展示内部身份或路径。

ARM-D-011：保持使用统计、访问管理、应用管理、设备管理、系统管理五项导航及五分类目录，无二级页签。

应用管理工具栏提供“确定性应用列表”和“分类规则管理”；分别打开独立可滚动面板，移动端面板全屏、关闭操作可达。产品列表管理类型、孩子分类、确认范围、变种及解除关联；规则面板展示条件/排除/自动或建议/结果/来源/启用状态。

规则包导入先显示新增/修改/冲突/命中应用/目标孩子，逐项批准，不自动覆盖明确配置。目录显示安装未使用、预配置未发现、使用过未发现、分类保存/设备应用/建议状态；不显示原始身份、路径、SID、凭据。疑似游戏/视频优先，完整已发现清单可查看。系统日志和访问配置保持不变。
