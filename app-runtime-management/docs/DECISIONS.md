## 2026-10-09 程序实例与应用身份三层模型（本层概念设计已固定，规则建立与表达待讨论）

本条固定PO逐项确认的概念，作为后续设计基线；不表示当前代码、契约或已安装版本已经实现。既有ARM-D-033的产品关联单一来源原则保留，但现有runtimeIdentity不得直接视为下述代码实例；身份识别成功不得成为基础落账或统计的前提。

### 上位产品原则与轻量处理取舍

遵循根DECISIONS.md同日“辅助工具，可靠性优先于精确实时”原则：本产品不是严格监管系统，允许适度误差、同步和识别延迟、事后修正。三层分工用于减少重复逻辑，不得演变为每次使用都必须即时证明完整身份的门槛。

- 扫描与运行监测是共同识别流程的发现入口，不各自判断产品归属；扫描不产生孩子使用记录，识别不阻塞使用和落账。
- 首次扫描、低频兜底补扫与运行时补漏即可构成首版发现路径；安装/更新事件监听是可选优化，不要求覆盖全部事件。扫描暂未发现不等于删除历史实例、归属或用量。
- 优先复用缓存，通过低成本变化线索决定是否后台重新检查，不要求每次运行都全量计算文件哈希或重复昂贵校验。确切检测、缓存及失效机制留待后续设计。
- 安装变化与规则更新允许短暂滞后；按受影响范围分批处理，不因新证据暂缺、单次采集或同步失败使整个统计失效，不无限重试。
- 同一实例的有效扫描与运行证据应补充而非整条相互覆盖；不同实例的证据不能伪装成同一份已核实事实。存在疑问时后台复查，依据不足保持未识别，不为识别率猜配。

程序实例的“固定位置＋固定内容”定义保持不变，但采集不承诺实时发现内容变化。PO接受同路径文件更新的有限发现延迟，以及间隔内少量使用可能沿用旧实例归属。确认文件变化后，后续记录采用新实例；过去实际替换时刻无法确定时不猜补、不为精确恢复更新瞬间改写原账。可以明确纠正的产品归属按规则修正，不宣称每条记录都实时验证过文件内容。

不为身份归属首版额外引入实时文件完整性监控、全事件监听、复杂证据评分、多端强一致或每次统计查询重新验签。正常可用、失败不拖垮、资源开销可控、能够解释和修正是验收重点。该容错不允许跨孩子串账、重复累计或把未知伪装成确认；统计使用稍旧信息的容错不自动扩展为依据未确认猜测触发新的强制封锁。

### 程序实例（此前称代码实例）

程序实例与此前的“代码实例”指同一概念：某台机器上、指定位置、内容固定的一份实际可执行文件。内容范围为实际执行文件，不是整个安装目录或应用包；下文保留的“代码实例”不是另一层对象。

- 同内容位于不同位置，是不同代码实例；同位置的执行文件内容变化，是新代码实例。
- 同一代码实例多次启动或产生多个进程，仍是同一个代码实例，不以PID建立永久身份。
- 辅助可执行文件有自己的代码实例；配置、资源等其他文件变化不改变该执行文件的代码实例。
- 安装版与便携版在此基础层没有区别；安装方式不参与有效用量判断。
- Child ID不定义代码实例，而定义用量归属；不同孩子使用同一代码实例，分别记录用量。

### 原始落账与基础统计

原账记录哪个孩子、在什么来源上、使用哪个代码实例、产生了多少有效使用整数秒。Child ID是用量归属主键，机器、系统用户、会话为来源属性；不是用Child ID单独标识一条记录。

有效用量仍遵守既有前台、活动、idle及切片规则，进程存活时间不直接等于使用时间。本条不修改计时、结算或上传边界。落账和代码实例基础统计不依赖应用身份、产品名称、家族、分类或关联成功。无法识别产品的有效时长必须保留并可统计，后续关联不改写原始事实。

### 应用身份与关联

应用身份代表用户可独立使用、家长可独立理解和管理的应用主体，例如Word、Chrome；不是单个窗口、快捷方式或进程。“使用焦点”指产品功能意义上的主体，不是操作系统当前获得焦点的窗口。应用身份是稳定的管理对象，名称是可修改属性，不是代码实例的唯一标识。核心关系为“代码实例→应用身份”，多个代码实例可以归属同一应用身份。

安装扫描和运行监测提供实例证据，规则执行生成具体归属；人工介入检查依据并修正规则，必要时审视原则，不直接维护实例映射。这些不是不同的落账机制。未建立关联时呈现“未识别程序实例使用时长”；后续关联或纠正关联只影响身份层归集，不增加或重复计算基础用量。

“未识别”指尚无应用身份关联；“未归类”指已知应用身份但未设置学习、娱乐等分类。二者不可混用。应用管理增加未识别代码实例管理层；具体界面与操作流程尚待设计，不能把讨论建议视为已批准UI。

### 产品归属原则

- 套件是组织关系，不吞并成员产品的独立身份；Word与Excel分别管理。
- 普通版本、发行渠道和平台差异默认不拆应用身份；面向用户的独立产品分别管理，不凭同名合并，也不因版本号不同自动拆分。
- 专用辅助程序、安装向导和更新程序归入目标应用，不另拆应用身份。
- 服务多个产品的共用更新器、安装或管理工具拥有独立身份，不把它的用量任意分摊给所服务产品。
- 启动平台与被启动应用分别核算；例如Steam与其启动的游戏，启动关系不构成归属关系。
- 模拟器作为独立应用管理和统计；首版不承诺识别内部应用，不引入随内部内容动态切换应用身份的机制。内部内容未知不等于模拟器身份未识别。
- 是否产生有效主使用时长由既有计时规则决定，不由部件名称或归属决定。后台自动运行不因存在进程而自动计时；辅助、安装或更新窗口符合前台活动条件时正常落账，再按关联归集。

### 三层归属体系

三层集中管理、职责明确；本节取代此前“人工直接确认并维护关联结果”的表述：

| 层次 | 职责 | 边界 |
|---|---|---|
| 产品归属原则 | 定义产品边界，由代码实现约束 | 不把具体软件名单写死在原则代码中 |
| 产品归属规则表 | 根据可核验依据确定目标应用身份 | 集中维护、跨Child ID复用；可以覆盖产品系列，也可以窄至确定的文件内容，不引入孩子级归属特例 |
| 程序实例产品归属表 | 保存孩子范围内具体实例的确定归属 | 按Child ID隔离，只由规则执行生成，不直接手工修改 |

原则与规则均须集中管理，不能将原则仅留在聊天、将具体规则散落在各端扫描、统计及页面中。应用目录提供稳定应用身份，具体规则引用目标身份。本机可以执行同步下来的规则，但不能形成第二套权威规则或不同的归属逻辑。统计和管理读取第三层映射，不在每次查询时联网或重新执行识别。

Child ID是第三层的管理范围，不是程序身份的识别依据，也不加入程序实例本身的定义。同一第二层规则可用于不同孩子，分别生成各自隔离的第三层映射，不能把一个孩子的映射直接当成另一个孩子的管理结果。“实例关联结果”就是第三层表的内容，不另建同义权威数据或人工覆盖入口。

第二层规则覆盖范围可以宽，也可以窄。即使当前只匹配一个实例，只要依据不依赖孩子的特殊指定，仍可表达为可复用规则；例如确定文件内容的副本可在不同位置被识别，再各自产生实例映射。覆盖对象少不是增加孩子特例或绕过规则直接改映射的理由。规则库不等于应用目录，规则也不等于具体映射。

### 纠错与人工介入

1. 发现未识别或错误归属，人工检查证据和规则，不直接修改第三层。
2. 规则缺失或错误，补充、修正规则表；表达能力不足时，审视原则及实现，不引入孩子级归属特例。
3. 错误来自采集、匹配执行或同步时，修正相应环节，不修改正确规则迁就错误数据。
4. 根据修正后的依据与规则重新生成受影响映射；禁止直接覆盖第三层，禁止由第三层自动反向修改规则。

未识别是合法、可处理的状态。证据不足时继续保留未识别，不猜配，不阻断原账和基础统计。人工判断不自动推广为通用规则；必须明确修正规则或原则后再生成映射。上述为概念流程，不预定规则建立方式、格式、算法、物理表结构、修订发布机制、同步协议或管理界面。

### 统计职责分层

基础统计按代码实例表达有效使用事实；应用身份层根据关联形成产品归集、分析和管理视图。此分层不意味着新增重复原账、重复计时、上传体系或配额账；具体持久化与查询结构尚未确定。并发用量沿用已确认的时长计算规则，不能把产品明细机械相加代替权威总量。

身份关联与分类配置是不同关系。确认或纠正关联后，可以更新已确认适用的实例及历史范围内的产品归集，包括更早历史；原账和基础时长保持不变，不重复计时。分类更正仍遵守既有本日／本周规则，不因身份补齐而自动重算更早历史分类。未识别状态不阻断基础统计，但不据此宣称产品识别或管理覆盖完整。

## ARM-D-036：卸载撤销不可逆与窄权限结果确认

## ARM-D-028：Service 重启接管既有 Session Agent，退出事件 fail-safe

2.5.1 原地升级后，Windows Restart Manager 未结束既有 Session Agent；旧进程继续持有同会话 mutex，新进程正常以 0 退出。Service 对该已退出进程设置 `EnableRaisingEvents` 时抛出 `InvalidOperationException`，未处理的异步退出链使 Service 以 1067 停止。2.5.2 必须先按安装路径与 session 精确发现并接管既有 Agent，只有无既有实例时才启动；启动／接管期间的进程退出竞态不得逃逸为 Service 未处理异常。退出回调只处理当前登记 PID，避免旧事件误删替代进程。升级、Service 重启和修复不得依赖人工结束孩子会话进程。

## ARM-D-019：按变更影响选择测试并复用精确 SHA 证据

## ARM-D-016：客观应用类型与孩子管理归类永久分离

PO 于 2026-09-18 补充确认：普通应用、系统应用和技术记录属于云端产品目录投影，不得依赖终端版本。Agent 只上传经过验证的 `packageId`、签名摘要、产品/变体关系等事实；Runtime Worker 是 `applicationOrigin`、`manageability` 和最终页面分组的唯一权威。contract 中 Agent 可选上传的 `applicationOrigin` / `originEvidenceCode` 仅为 advisory evidence，不能覆盖云端规则。系统包规则变化只发布 Worker，不要求升级安装包；只有新增底层证据采集或本地执行能力时才升级 Agent。

应用管理的五个孩子分类目录保持不变。每个目录右侧同页显示默认展开的普通应用和默认折叠的系统应用；搜索命中系统应用时自动展开。系统应用默认仍为未归类，不因系统归属自动改变分类、配额、账本或历史 Segment。技术记录继续位于系统管理，不提供分类按钮。

## ARM-D-014：安装产品、应用变体与技术记录三层目录

PO 确认实施并要求生产发布（2026-09-16）。家长应用目录的主对象是可管理产品，不是安装入口、快捷方式或运行进程。Windows Uninstall Registry / MSIX 等可信安装记录形成 `InstallationProduct`；Start Menu、包内应用、便携执行体和运行身份形成 `ApplicationVariant`；组件、更新器、卸载器、helper、诊断工具及证据不足宿主形成 `TechnicalRecord`。

套件默认按安装产品聚合，LibreOffice 等产品只显示一个主行，入口保留在可展开变体中；家长明确“拆分管理”后，指定变体才可拥有独立分类。主清单以 Windows 可管理安装产品为基线，但不机械复制系统设置清单：驱动、runtime、维护组件和系统管理入口仅保留技术审计。通用浏览器/WebView/PWA 必须依赖可信 AUMID、package identity 或家长确认去重，无法确认的宿主不得进入主目录。

生产复验补充：安装记录缺少结构化组件标志时，redistributable、runtime、maintenance service、installer 等名称语义只能触发 `review`，不得据此删除事实或自动确认产品。产品名称的版本、架构或渠道装饰归一化只允许把唯一安装产品旁的孤立入口降为“可能变体”，不构成持久合并、分类继承或跨产品身份确认。

盘点完整性按来源结算。单项解析错误只记 warning；只有来源级枚举失败才阻止该来源的缺失对账，其他成功来源仍可独立清理陈旧 installed 投影。旧 v1 客户端继续全局 fail-closed。所有清理只改变安装状态和目录投影，不删除原始观察，不改写 UsageSegment、历史时长、分类或配额键。

## ARM-D-013：产品应用投影与技术进程记录分层

PO 确认修复（2026-09-16）。`runtimeIdentity` 是不可变账本的技术身份，不等于家长可管理的产品应用。应用目录只收纳已确认产品，或具有可靠安装证据且角色为主应用的具体平台实现；已确认产品的多个技术实现合并为一个产品行，但仍保留全部实现供策略投影。分类计数和分类操作只针对这些可管理对象。

组件、安装器、updater、helper、宿主进程和只有历史进程短名的旧记录不得因为“曾产生 Segment”自动成为应用。组件/瞬态对象默认隐藏，候选和证据不足的历史身份进入只读“技术进程记录”，可审计但不能分类；不得依靠名称黑名单删除 `wixstdba`、`olk`、`w` 等特例。待后续取得包身份、签名、binary hash 或人工产品关联后，才可晋升为可管理对象。

本决策只改变产品目录/read model 与交互投影：原始 Segment、历史时长、配额键和上传 ACK 均不改写；技术进程是否应计入主账本属于独立 accounting 决策，本轮不隐式改变。

## ARM-D-012：发现对象降噪、可信关联与盘点完整性

PO 授权修复（2026-09-16）。安装对象、启动入口、运行身份和家长确认的产品不混为一谈。包的隐藏入口仅作为组件展示提示，不豁免运行计时；不同可见入口保持独立，不能因同包、同名或同签名者自动合并。相同已验证 binary/packageId 可关联旧运行身份，保留全部技术实现与原有配额键。Registry DisplayIcon 不作为主程序证明。友好名称优先于包名，无法解析时明确为名称回退。

默认目录优先主要应用，组件可通过完整发现筛选查看；已安装未使用也可归类。原使用未归类历史仍按原始账本读取，禁止追溯修改。scanId、来源结果、预期批次数/观察数及批次序号形成独立盘点协议；所有批次入库且完成标记收到后才称完整。未登录用户、失败来源和旧客户端均不能称整机完整。未知/中断扫描不推断卸载。

本轮只修代码、本地 additive migration 与客户端 2.2.1 包。保持配对、机器身份、历史账本、独立部署边界和未签名发布风险；不清理生产数据、不部署、不自动升级。

## ARM-D-011：应用发现、确定性产品与分类规则

状态：Active（PO 批准，本地实现；macOS 验收待环境）。家庭产品类型和可信身份关联共用；孩子明确分类独立。确定性产品列表与通用规则分别管理，规则逐条选择自动/建议。自动规则不能仅凭名称、路径或自声明类别生效；同层冲突保留旧有效分类，无旧配置则未归类。外部规则包必须预览差异后逐项批准，不能覆盖孩子明确配置。首次安装主动盘点，运行补充便携应用；盘点不形成 UsageSegment。关联合并/拆分可审计，不改写历史。Windows 接入 Service，macOS 仅显式只读发现；不生产部署、不阻止进程、不共享 Santa 身份协议。
