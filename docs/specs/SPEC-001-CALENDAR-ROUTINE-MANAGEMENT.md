## Goal

建立独立的日历例程产品模型，用固定自然时间范围描述 Chrome 在某段时间内通常允许使用的内容。日历例程最终取代当前独立的“时间段管理”产品概念，同时继续复用网站性质、使用性质、时间配额、安全规则和用量账本构成的底层能力。

日历例程只决定当前是否允许使用某类内容，不永久修改网站分类，不改变时间的统计性质，也不改变配额归属。

## Problem

当前时间段管理分别维护学习、复合和休息时段，可以表达简单的模式可用窗口，但不能清楚表达：

- 一个有名称和明确用途的日常安排；
- 按星期重复并具有生效日期范围的周期安排；
- 只在指定日期发生的一次性安排；
- 一次性安排对周期安排某次发生的明确覆盖；
- 同一安排中网站管理类型、具体网站和特殊网站对象的组合范围；
- 当前访问决策由哪一个时间安排产生。

继续直接扩展 `timeWindows.daily` 会让旧的模式窗口结构承担新的产品语义。日历例程应成为新的产品真值，现有时间窗口只在后续技术迁移中作为兼容输入或执行适配能力。

## Core Definitions

### 基础场景

没有日历例程生效时，系统直接执行基础场景：网站性质决定使用性质，使用性质决定消耗的时间配额，配额决定该类使用能否继续；黑名单、安全规则和其他不可覆盖限制始终优先。基础场景本身是完整可运行的产品场景，不依赖额外时间窗口。

### 日历例程

日历例程是在固定自然时间范围内生效的内容使用策略。它包含时间安排和允许内容范围，并在生效期间成为基础场景之前的内容访问约束。

### 周期例程

周期例程按星期组合重复，并可设置生效日期范围。每次实际发生称为一个例程实例；修改某个实例不应隐式改写其他日期的实例。

### 一次性例程

一次性例程只在指定本地日期和时间范围内生效。它可以明确覆盖同一时间内周期例程的当次实例，但不修改周期模板及其其他实例。

### 允许内容范围

一个日历例程可以组合网站管理类型、具体网站或独立服务子域，以及已支持的特殊网站对象。例程内选中的管理类型、具体网站和特殊对象取去重并集。黑名单、安全对象和其他不可覆盖对象不能作为例程放行内容。

### 有效日历上下文

任一时刻的有效日历上下文只能是基础场景、一个周期例程实例，或一个明确覆盖周期实例的一次性例程实例。运行时不得临时合并两个不同日历例程来解决配置冲突。

## Scope

This spec includes:

- 日历例程的核心产品定义；
- 周期例程和一次性例程；
- 时间冲突、一次性覆盖和实例边界；
- 网站管理类型、具体网站和特殊对象组成的允许范围；
- 日历例程与网站性质、使用性质、时间配额和安全规则的关系；
- 日历例程开始、结束、取消、停用和配置更新时的用户可见行为；
- 功能验收标准和后续实现必须覆盖的测试场景。

## Out Of Scope

This spec does not include:

- 任务管理的进度、暂停、完成或外部事件模型；
- 日历例程 schema、storage key、数据库表或 migration；
- Worker API、同步协议或离线冲突解决方案；
- 现有 `timeWindows.daily` 的迁移、兼容适配和删除步骤；
- 时区、夏令时、跨午夜和设备时钟漂移的技术方案；
- Pages、Popup、本地 Admin 的具体视觉稿和组件布局；
- 用量账本是否增加例程快照字段；
- 月度、自定义间隔或类似 cron 的高级重复规则；
- 对当前代码、API、数据库或运行逻辑的任何修改。

## User Behavior

### 创建和编辑

- 家长可以创建周期例程或一次性例程。
- 周期例程至少支持按星期组合重复，并可设置生效起止日期。
- 一次性例程指定本地日期、开始时间和结束时间。
- 每个例程具有可识别名称和允许内容范围。
- 开始时间必须早于结束时间；跨午夜表达方式留待技术设计确定。

### 冲突处理

- 任一时刻最多只能有一个有效日历例程。
- 两个周期例程的有效实例不得产生未解决重叠。
- 两个一次性例程不得产生未解决重叠。
- 一次性例程与周期实例重叠时，必须明确记录为当次覆盖关系。
- 创建或编辑产生冲突时，保存前必须选择替换、拆分或取消，不能留给不同终端在运行时自行裁决。
- 日历例程之间不自动合并允许资源。

### 生效与恢复

- 进入例程开始边界时，系统立即按该例程允许内容重新评估当前网页。
- 到达例程结束边界、例程被取消或停用时，系统立即恢复当前仍生效的日历例程；没有其他例程时恢复基础场景。
- 配置更新改变当前有效例程或允许范围时，系统必须重新评估当前网页。
- 当前网页不属于新的允许范围时，系统按当时有效策略提醒或阻断。

### 网站性质与配额

- 日历例程不改变网站的永久分类。
- 学习、复合、受限娱乐和未归类网站继续按各自现有性质计时、扣减配额和进入归类流程。
- 配额耗尽时继续执行现有配额规则；日历例程不赠送时间、不借出额外时间，也不绕过配额阻断。
- 黑名单、安全规则和其他不可覆盖限制始终高于日历例程。

## Data And State

本规格只定义概念状态，不指定持久化字段：

- 例程模板：启用、停用；
- 例程实例：计划、生效、被一次性例程覆盖、结束、取消；
- 当前有效日历上下文：基础场景、周期实例或一次性实例；
- 访问决策上下文：有效例程身份、配置版本和允许内容范围。

日历例程配置应是后续实现的唯一产品真值。旧时间窗口只能作为迁移输入或兼容输出，不能与日历例程形成可独立编辑的双重真值。

## Acceptance Criteria

1. 产品界面和文档只使用“日历例程”作为该功能的正式名称。
2. 日历例程能够表达周期安排和指定日期的一次性安排。
3. 任一时刻最多只有一个有效日历例程。
4. 未解决的周期或一次性例程冲突不能保存。
5. 一次性例程能够只覆盖周期例程的当次实例。
6. 一个例程能够组合网站管理类型、具体网站和特殊网站对象，并按去重并集形成允许范围。
7. 没有例程生效时，系统恢复完整的基础场景。
8. 日历例程不会改变网站分类、使用性质或配额归属。
9. 黑名单和不可覆盖规则不能被日历例程绕过。
10. 例程开始、结束、取消、停用和当前配置变化都会重新评估当前网页。
11. 边界重新评估不会造成重复计时或重复扣减配额。
12. 后续实现不会让日历例程与旧 `timeWindows.daily` 成为可独立编辑的双重真值。

## Required Tests

- Unit: 周期实例展开、一次性实例、时间冲突、一次性覆盖、允许范围并集和当前有效上下文解析。
- Integration: 日历边界与网站分类、配额检查、当前网页重新评估的组合行为。
- E2E: 周期例程、一次性覆盖、无例程基础场景、配额耗尽和例程结束恢复。
- Manual: 家长创建和编辑例程、解决冲突、查看当前有效例程与允许范围摘要。
- Release gate: 由后续实现设计确定；本 Draft 不定义发布版本或发布门禁。

## Release Risk

Known release risks:

- 若日历例程和旧时间窗口都可独立编辑，可能产生配置双重真值。
- 若冲突留给运行时临时解决，不同设备可能得到不同有效例程。
- 若日历例程重新解释网站性质，可能破坏统计和配额口径。
- 若边界没有触发当前网页重检，旧页面可能在新规则下继续运行。
- 若旧客户端在不理解日历例程时收到全开放时间窗口，可能失去原有时间限制。

## Rollback Risk

Rollback concerns:

- 现有 `timeWindows.daily` 的兼容和退出策略必须在实施前单独批准。
- 混合版本期间需要保留从日历例程单向生成旧客户端兼容窗口的能力。
- 若例程身份进入用量账本快照，回滚时必须保留历史 segment 的原始解释，不得按当前规则重算。
